# 阶段 02：角色拆图、图层顺序与表情分离

输入：阶段 01 通过检查的骨骼设计、同一张原图，以及 AI 或设计者给出的部件边界。

输出：独立透明 PNG、部件与图层顺序清单、沿实际外形着色并编号的检查网页、空面部及独立表情素材，以及本阶段人工确认 checkpoint。

## 网页使用与交接卡

路径中的 `P` 为当前角色项目绝对路径；见[统一目录与调用](../references/project-artifacts.md)。

- **调用工具**：`scripts/build_part_review.py` 复用 `assets/part-review.html`，建议输出 `P/stage02-review.html`。
- **AI准备／提交**：有效的01确认、`P/input/split.json` 及其引用的前景／部件／表情蒙版。蒙版和相对路径按[拆图格式](../references/part-review-format.md)准备，边界由AI或设计者提供。
- **用户怎么用**：点击彩色外形、编号或列表选层，查看原图／合成／单层，调整层序；用“编辑轮廓”在指定两层之间转移像素。分别查看空面部、独立五官和叠回效果，记录需修问题。
- **保存与整阶段提交**：每笔完成后的轮廓与其他设计修改自动保存。问题处理后等待保存完成，点“确认切片与表情拆分”；单层已检查和下载PNG不等于整阶段提交。
- **产出在哪里**：网页在 `P/stage02-review.html`；初始PNG、parts.json和归属图在 `P/stage02-review.assets/`。网页修改后的PNG、坐标、层序与备注以 `P/stage02-review.workflow/draft.json` 为准，确认结果为同目录 `confirmed.json`；初始assets不会自动随网页编辑更新。
- **下一阶段拿什么**：阶段03检查02的有效确认，只读取其 `design.parts/order/face` 中的最新内嵌素材及坐标，保留节点；需要独立PNG时从该快照解码导出，不能直接拿初始assets继续制作。

## 1. 读取上游确认结果

运行 `scripts/review_checkpoint.py check --project <阶段01项目目录>`。只有退出码 `0` 且 `approval_scope` 为 `skeleton-layout` 才进入正式拆图；读取确认文件中的 `design`，保持图片、像素坐标、节点 ID 和设计者已定部件可追溯。

不要从骨骼节点直接生成矩形切片。节点指定运动支点，部件轮廓仍须根据原图单独标注。补充或细分部件时说明原因，保留原部件与新部件的对应关系。

开发或讲解工具时可以用生成器 `--demo` 读取未确认草稿；演示网页必须明确标记，不能产生正式阶段放行，不能以此绕过用户的骨骼确认。

## 2. 定义前景与部件边界

实际观察原图，按部件填写原图尺寸的蒙版、多边形或椭圆，格式见 [第二阶段数据与生成方式](../references/part-review-format.md)。优先使用精细蒙版表达发丝、蕾丝、细带等复杂轮廓；多边形只是可用的标注方式，不代表边界已准确。

- 原图有背景时，明确提供角色前景蒙版；透明底可沿用已有 alpha。不把背景分进身体部件。
- 保留衣纹、明暗和原图 alpha；按实际外形导出透明 PNG，记录每块在原图的偏移。
- 输入 `parts` 的顺序决定像素分配优先级，先定义的先占像素；`order` 独立规定绘制顺序，两者不混用。
- 默认不自动吞并未归属前景像素。生成器报告缺口时先修边界；只有明确选用 `unclaimed: nearest` 才作最近区域分配，并检查其影响。
- 色彩规则只作候选区域筛选；头发、肤色、白布相近时不能据此断言语义归属正确。
- 本阶段区分原图可见像素与缺失遮挡。一般部件的隐藏区域记录为下一阶段修补项，不假装已恢复；面部去五官后的底色是本阶段的必要例外。

## 3. 单独拆出面部表情

对实际可见的表情元素分别建立素材：左右眼及眼睑睫毛、左右眉、嘴；红晕、泪滴或表情符号按角色需要独立。鼻部线条根据设计决定是否拆出；不可见的五官不凭空生成。需要自然眨眼或眼球转向时，按[眼部拆分与眨眼设计](../references/eye-blink-design.md)明确眼白、虹膜／瞳孔、高光、上下眼线与眼睑底色，避免直到动画阶段才发现合并眼片无法独立遮挡；静态检查可暂用合并片，但须记录其动画局限。不强制所有角色采用同样粒度。

同时保留一张无原表情的面部底图：

- 保留脸型、耳朵、肤色和明暗，去掉所有已拆出的原五官。它可以是独立脸层，也可以包含在头部底图中，但隐藏所有表情后必须能直接检查到空面部。
- 不把表情区域挖成透明洞；在去除位置修补皮肤，保持原有底图 alpha。
- 可以用周围皮肤作初步平滑修补，明确它是待检查的估计。复杂光影、发丝交叉或纹理无法自然延续时，使用设计者提供的空面部或安排局部重绘，不强行标为完成。
- 导出每个表情元素的透明 PNG，保持原坐标与头部节点关联。部件轮廓与修补边界应避免夹带刘海、脸缘及不必要的皮肤；边缘需要少量覆盖时明确说明。
- 检查三种画面：隐藏表情后的空面部、透明底上的独立表情、重新叠回后的完整脸。关注五官残留、透明孔洞、肤色块、睫毛缺损和重复五官。

## 4. 生成并打开网页检查

使用本 skill 自带生成器，路径相对 skill 根目录：

```bash
python scripts/build_part_review.py --upstream character-review.workflow --config split.json --out parts-review.html
python scripts/review_checkpoint.py serve --project parts-review.workflow
```

需要 Pillow、NumPy、SciPy。优先使用已有环境。生成器不是自动部件识别模型；AI/设计者提供边界，脚本执行切片和初步面部修补。

在应用浏览器打开服务返回的 URL；独立 HTML 可用于离线预览，正式确认需通过本地服务。

网页检查要求：

- 在原图上按每个 PNG 的真实 alpha 外形叠色并描边，颜色各异；不能用包围矩形冒充部件轮廓。
- 用数字对应图层顺序：`1` 最后，数字越大越靠前。列表上方显示靠前图层；部件稳定 ID 不随编号变化。
- 点击轮廓、编号或列表可定位部件；支持单层查看、原图与切片合成切换、缩放及顺序调整。重新排序后立即更新编号。
- 表情层始终在空面部之上；骨骼父子关系不替代绘制顺序。运动时需动态换序的部件在备注中记录，此网页只确定静态基础顺序。
- 独立展示空面部与表情预览，允许隐藏表情检查底图、叠回比较，并下载各层 PNG。
- 设计者可用“编辑轮廓”画笔调整部件接缝：先选当前层及相邻部件，“扩入当前层”从相邻层取像素，“划给相邻层”将当前层像素转交过去。画笔直径使用原图像素；只处理指定两层，保持透明背景，不留下未分配缺口。不允许把部件整个涂空。
- 按住 Alt 或中键拖动平移，滚轮缩放；Escape 取消当前笔或退出编辑。每笔松开后更新两层 PNG、实际轮廓、裁剪坐标与编号锚点，支持撤销/重做。编辑后的两层回到待检查，阶段确认失效。
- 面部与表情也能用画笔调整，不锁定 `face.roi`。选中表情时自动选择面部为相邻层：“退回面部”把减掉区域的原像素贴回面部，“从面部扩入”从当前面部取像素加入该表情，其他表情不被覆盖。也能选中面部反向操作。
- 表情扩入时保留下面完整的面部底图；首次编辑前保存一份底色备份，之后将曾退回的区域再扩入表情时，恢复该位置已有的底色。普通扩边不调用 AI 重新修补或生成新像素。设计者主动把眼睛等内容退回面部时，这些内容会出现在面部底图中，应在空面部预览中检查，必要时再扩回表情。
- 网页不是遮挡补全工具，不会生成原图中看不见的像素。实际需要重绘底色或修补缺失内容时另外安排素材修订，不用它阻止常规表情边界调整。
- 设计者可把其他问题标为 `needs_repair` 并备注。只升级网页工具时保留当前任务和草稿；需要重跑切片时先读取最新草稿中的 PNG 和坐标，不能用初始蒙版覆盖人工修改。

## Checkpoint：切片与表情检查

复用 `review_checkpoint.py serve/check/wait`。项目和确认文件与阶段 01 分开，阶段为 `02-part-separation`，确认范围为 `part-separation`。

1. 设计者通过网页检查轮廓、编号顺序、空面部和每个独立表情。
2. 草稿修改自动保存；画笔调整轮廓、改名、颜色、图层顺序或问题状态变化会撤销原确认。缩放、单层查看等预览操作不撤销确认。后续素材以最新快照中的内嵌 PNG 为准，不能继续读取生成时的旧 PNG。
3. 人工点击“确认切片与表情拆分”，服务写入本阶段 `confirmed.json`。有 `needs_repair` 图层时不放行；整阶段确认可将待检查图层统一接受。
4. AI 不代点确认，也不制造标识。活动任务以有界 `wait` 等待人工结果，进入后续阶段前再 `check`，只使用确认快照中的实际图层顺序与素材。
5. 检查同时验证上游骨骼仍是本阶段生成时的有效确认版本。上游发生修改或重做确认后，原拆图确认不放行，需核对并重新生成。

确认后可进入[阶段03：补全与局部SVG重绘计划](03-material-completion.md)，独立查看全部切片并选择处理范围。计划确认不表示修复已执行；实际重绘与动画仍需后续建立。

## 完成条件

部件轮廓与坐标正确、透明边缘无明显夹带和碎片；图层编号与实际合成顺序一致；表情独立且空面部无残留和透明孔洞；重新叠回与原图对齐；问题已解决或明确保留在不放行状态。正式完成要求本阶段 `check` 返回 `0`，不能用演示页或普通文件导出替代。
