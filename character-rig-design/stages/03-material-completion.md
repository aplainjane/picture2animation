# 阶段03：独立部件检查、补全与局部SVG重绘计划

输入：阶段02的有效人工确认快照，包含设计者最终调整过的内嵌PNG、原图坐标、层序和骨骼。

输出：全部切片的独立检查网页、AI逐部件处理建议及范围、设计者可分别勾选补全／局部SVG／边缘清理的计划、独立人工checkpoint。**此阶段实现的是计划检查，尚不执行重绘。**

## 网页使用与交接卡

路径中的 `P` 为当前角色项目绝对路径；见[统一目录与调用](../references/project-artifacts.md)。

- **调用工具**：`scripts/build_material_review.py` 复用 `assets/material-review.html`，建议输出 `P/stage03-review.html`。
- **AI准备／提交**：有效的02确认和覆盖每个实际部件的 `P/input/repair-plan.json`，写明保留／补全／局部SVG／清理建议、理由和原图范围，格式见[计划数据](../references/material-review-format.md)。
- **用户怎么用**：浏览所有独立切片，搜索或筛选、放大查看建议区域；逐块勾选或取消补全、SVG、清理，补充备注，必要时撤销或恢复AI建议。
- **保存与整阶段提交**：选择和备注自动保存。等待保存完成，点“确认补全与重绘计划”；“导出计划 JSON”是备份。原始PNG在本页只读。
- **产出在哪里**：网页在 `P/stage03-review.html`；实际勾选与备注在 `P/stage03-review.workflow/draft.json` 的 `repair_plan` 中，有效计划为同目录 `confirmed.json`。本阶段不产出重绘后的PNG或SVG，原始repair-plan配置不自动回写。
- **下一阶段拿什么**：阶段04检查03的有效确认，读取 `design.repair_plan` 的实际布尔选项和备注，只执行已选择动作；不能直接执行AI原始suggestion或把计划确认当作素材结果确认。

## 读取与逐块判断

先运行 `scripts/review_checkpoint.py check --project <阶段02目录>`。正式流程要求退出码0、`approval_scope=part-separation`，只读返回确认文件中的 `design`，不用生成时导出的旧PNG替代人工修改快照。检查还会递归验证骨骼确认。

先看所有独立切片，再放大有疑问的部件并结合原图与节点判断。每个部件都要有明确建议，包括保留原样的理由；不能只给一份未解释的全选名单。

分别评估三个可叠加选项：

- **补全**：关节转动或部件独立移动后会露出的缺口、被前层遮住的连接、表情移走后的底片。先考虑预期动作需要的最小搭接；同节点固定遮挡、永不露出的区域可暂不补。隐藏结构是推测，标出范围和依据。
- **局部SVG重绘**：简单皮肤底形、眉线、红晕渐变、简单链／环／星形等有利于干净透明轮廓或后续形变的局部。复杂发纹、虹膜高光、衣褶和宝石优先保留原图，采用位图加SVG局部修补；不要默认整张矢量化。把位图嵌进SVG文件不等于完成矢量重绘。
- **边缘／散点清理**：误归属的衣片、发色夹带、浅色边晕、无意义的孤立像素。面积小不等于垃圾：鼻点、链节、睫毛、发丝和分离坠饰可能都是有效内容。此处先提议，由设计者检查，不能自动删除。

区分三种“空余”：裁切框外的全透明余量可以收紧并同步原图偏移；细长或多段部件包围盒内的合理透明区域不应填色；切片内部因取走前层而产生、运动时会露出的孔洞才需要补底。必要时建议将远距子片再拆组，避免为了节约包围盒而画出不存在的连接。

给补全／重绘建议标原图坐标中的局部范围、原因及优先级。虚线只是待核对的范围，不是新素材或精确分割结果。空面部的发肤交界、眼尾夹带和眉毛跨刘海处需单独检查，避免把原表情再烘焙回脸层。

需要眨眼时按[眼部拆分与眨眼设计](../references/eye-blink-design.md)检查眼线／睫毛能否独立变形、眼球与高光是否可被眼白遮罩裁切、皮肤与褶线是否误夹在整眼切片。缺少结构时提出细拆或局部补全，不把整眼缩放列为正式眨眼方案。闭眼轮廓可以局部SVG绘制，但应沿用原笔触与眼尾，虹膜纹理不整块矢量重画；仍由人工确认处理范围。

## 生成网页

配置与脚本见[计划数据格式](../references/material-review-format.md)：

```bash
python scripts/build_material_review.py --upstream parts-review.workflow --config repair-plan.json --out material-review.html
python scripts/review_checkpoint.py serve --project material-review.workflow
```

启动后在应用浏览器打开服务URL。所有部件独立显示，包含真实透明PNG、图层号、名称、建议理由、透明占比和小连通块候选；可搜索、筛选、放大、结合原图定位和查看建议区域。

用户可以分别勾选或取消补全、SVG和清理；允许全部取消，也允许给AI原本建议保留的层追加处理。提供设计者备注、恢复单项／全部AI建议、撤销与重做、计划JSON导出。建议与用户选择分开保存，不能把用户选择覆盖成“AI原本建议”。

预览尽量按有效alpha紧凑展示；原PNG、位移、节点和层序保持只读。透明占比和小连通块统计只用于检查，不用作自动重绘或删除阈值。纯浏览、缩放、筛选不改计划或确认状态。

`--draft-preview` 仅供上游未确认时开发检查页，页面明确标为草稿且后端禁止确认；不能拿它替代正式关卡。

## Checkpoint：处理计划确认

阶段ID `03-material-completion`，确认范围 `material-repair-plan`。沿用共用服务的 `serve/check/wait`。

1. 用户修改勾选或备注后自动保存至本阶段 `draft.json`，已有计划确认失效；所有原切片只读。
2. 人工点击“确认补全与重绘计划”后，服务才写出含完整选择及源素材快照的 `confirmed.json`；AI不代点或伪造文件。
3. `check` 同时验证本次run、最新草稿、源切片与AI证据未被替换，以及阶段02、01的确认仍匹配。上游改动后需读取最新快照重新评估，不能自动把用户的旧勾选套到新素材。
4. 活动任务可用有界 `wait` 等待，结束会话后的继续需要重新检查。用户仅口头认可、普通导出或打开页面不能代替标识。
5. 确认后的执行任务只能处理确认快照中对应选项为真的部件，并读设计者备注。此checkpoint批准的是计划，不能当作“已修复素材”放行动画。

## 后续执行约定

计划确认后按[阶段04：素材修复与结果检查](04-material-result.md)执行。保留原切片供对照，交付修复后的原位合成、独立素材与紧凑alpha裁切偏移，再设置独立结果确认。SVG局部底片必须是真实矢量路径，位图原画作为保留层；透明边缘不填背景色，隐藏补全不得漏到原本可见的外轮廓。
