# 阶段05：骨骼绑定与动作检查

输入：阶段04有效人工确认 `material-repair-result`。输出：刚性切片骨骼绑定、小幅待机与关节试动网页、绑定JSON、独立预览HTML及本阶段检查点。

## 网页使用与交接卡

路径中的 `P` 为当前角色项目绝对路径；见[统一目录与调用](../references/project-artifacts.md)。

- **调用工具**：`scripts/build_animation_review.py` 复用 `assets/animation-review.html`，建议输出 `P/stage05-review.html`。
- **AI准备／提交**：有效的04确认。按当前角色核对部件驱动节点；可通过 `--eye-guides P/input/eye-guides.json` 提供绑定原图哈希的六点建议和对应闭眼PNG，本阶段不会自动生成精修闭眼素材。
- **用户怎么用**：选部件修改驱动节点，选关节小幅试动，调整待机摆幅和周期；在表情放大窗口检查开合、闭眼贴图，进入“校准眼部六点”拖点和改带宽。发现露缝或表情问题写入反馈。
- **保存与整阶段提交**：绑定、待机参数、六点、带宽和反馈自动保存；播放、试动角度与普通表情滑杆仅预览。等待保存完成后点“确认绑定与动作检查”；关闭六点窗口或下载预览不放行阶段。
- **产出在哪里**：网页在 `P/stage05-review.html`；实际绑定和持久化参数在 `P/stage05-review.workflow/draft.json` 的 `rig`，确认结果在同目录 `confirmed.json`。网页可“导出绑定 JSON”和“下载独立预览网页”，下载位置由浏览器决定。
- **下一阶段拿什么**：阶段06检查05的有效确认，读取其完整design，原样保留 `rig.bindings/eye_guides`、实际采用的闭眼纹理、最终素材、节点及层序，再添加production动作。

## 输入与绑定

先运行 `scripts/review_checkpoint.py check --project <阶段04目录>`。使用返回的 confirmed.json 内 design，原样保留图片、部件PNG、裁切坐标、层序、空面部／独立表情、节点坐标和父子关系。尤其沿用人工擦除后的素材，不能重新运行早期生成脚本替换它们。节点或切片需要修改时，返回对应阶段修订并重新确认依赖链。

为每个部件选择一个已有驱动节点。两关节之间的刚性切片默认绑定靠近身体一端的节点，另一端作为末端位置，不能把 node_ids 当成蒙皮权重。头部和五官同步跟随头节点；头发和饰物可以跟随设计者已有附件节点。左右按角色自身方向核对。缺少明确驱动节点时先解决设计，不猜测新增人体骨骼。

```bash
python scripts/build_animation_review.py --upstream result.workflow --out animation.html
python scripts/review_checkpoint.py serve --project animation.workflow
python scripts/export_review_history.py --project-root <角色项目目录>
```

打开服务返回URL。生成会创建新的run；恢复现有任务只启动其workflow服务，不覆盖人工绑定草稿。

## 动作与检查网页

原姿势必须严格使用素材原坐标和层序，无额外缩放或重绘。运行时每个节点局部变换为 `T(原图支点) × R(角度) × T(-原图支点)`，世界变换为父节点世界变换乘局部变换。父节点带动所有后代；静止时所有矩阵为单位矩阵。

先提供温和的正弦待机，脚和腿保持稳定，胸、头、头发和坠饰小幅转动。默认值由当前节点语义决定，是AI建议，不能视为设计者确认。网页允许更改驱动节点、单节点摆幅、周期和问题备注；原节点位置与层序在本阶段只读。关节试动可选择节点手动旋转，或播放小幅往复动作，检查肘膝、发根、袖口、裙腰等连接处是否露缝。原图对照、隐藏表情、拖动、缩放和时间轴只影响预览，不修改检查点。

实际核对：静止合成与阶段04素材重组一致；父节点旋转只带动对应子树；循环首尾一致；PNG与空面部保留原画细节。动画露缝需要回补时记录部件、节点、角度和部位，并标记“需要修订”，不要为了通过检查悄悄修改上游素材。

### 表情预览

提供独立面部放大窗口，与整身画面同步，跟随脸底所绑定的节点。支持原表情、双眼闭合、单眼闭合、嘴部开合、眉毛抬落及手动滑杆；左右按角色自身方向标明。闭合／开合动作可单独循环播放，和身体待机独立控制。“恢复原表情”应逐像素恢复原五官，不能改动空面部、脸缘和肤色。

眨眼按[眼部拆分与眨眼设计](../references/eye-blink-design.md)执行，参考其中已核对的Live2D官方资料。使用开合参数改变眼裂／眼睑形状，以动态遮罩裁切保持正常尺度的眼球与高光；眼线／睫毛跟随眼睑变形。完全闭合使用该眼独立的闭眼贴图，接近闭合时平滑过渡，不能压扁整个眼片或在最后一帧硬切无关细线。分别设计闭合、停留、睁开时长，检查开眼／半闭／闭眼与所有中间状态。

现有合并眼片使用可编辑六点控制架：两端眼角、上睑两点、下睑两点，平滑曲线围出局部范围。点击“校准眼部六点”在原眼图拖动；上、下睑向共享闭合线贴合，范围外源像素保持不动，仍继承头部整体变换。不使用颜色阈值把“非眼线”像素直接删除。六点与带宽存入 `rig.eye_guides`，人工修改会保存草稿并撤销旧确认，开合滑杆仅预览；离线历史只读六点。可用 `--eye-guides proposals.json` 提供绑定原图哈希的AI初始建议，恢复时保留已有人工坐标。

界面明确六点预览不是精修的Live2D模型；范围不准仍可能夹带皮肤或残留眼线，正式素材需要回到前阶段细拆与补全并重新确认。嘴部当前仍是切片缩放与临时闭嘴曲线的初步示意，不能宣称已有笑、怒或完整口型库。当前支持明确ID `eye_l/eye_r/brow_l/brow_r/mouth`；缺少相应独立层时禁用该项，需要其他命名时先显式映射角色部件。

为左右眼分别准备透明闭眼PNG，保持原眼图画布尺寸和局部坐标，匹配已调整的眼角、倾斜、眼线颜色与粗细。SVG重绘可保留源文件，再栅格化为PNG。将 `closed_texture:{w,h,src:"data:image/png;base64,..."}` 放入对应 `rig.eye_guides` 或 `--eye-guides` 建议项；网页将新建议的贴图补到缺失项，保留草稿已有贴图和人工六点。当前预览在开合0.12至0之间平滑过渡，0时仅在选区内显示闭眼贴图，选区外保留源像素。缺贴图时保留派生预览，但不能宣称完成贴图替换；检查点、JSON、独立HTML和历史应保留实际采用的贴图。仅播放不保存，下一次设计保存或人工阶段确认时才把采用的建议写入rig。

普通表情开合控件仅改变预览状态，不写入rig草稿、不改变检查点；六点／带宽是例外，属于需持久化的绑定设计，会随JSON和整阶段确认导出。离线快照与独立HTML允许试动；原图对照和隐藏表情优先显示，界面提示当前状态。真正制作表情资产时另行检查局部重绘与口型，不回写已确认素材。本阶段原姿势校验应在原表情下进行，同时验证复原、单眼独立控制、面部随头运动、选区外像素保持原位以及纯预览无POST。

导出的JSON保存节点、层序、绑定、摆幅、周期及上游版本，配合阶段04素材使用；独立HTML内嵌素材，可离线播放，不能提交人工确认。当前是单骨刚性切片动画检查，尚无网格蒙皮、IK、成品动作编排或Spine工程导出；不要将预览JSON描述成Spine格式。

## Checkpoint与回看

阶段ID `05-skeleton-animation`，范围 `skeleton-animation-rig`，递归绑定阶段04及全部上游版本。用户点击“确认绑定与动作检查”才生成有效 confirmed.json；AI不得代点。标记“需要修订”时禁止确认。更改绑定、摆幅、周期、检查状态或备注会保存草稿并使旧确认失效；普通播放与试动不影响确认。

有界等待人工确认，恢复时重新check。未确认停在本阶段；确认后根据用户希望制作的具体动作继续。每次交接导出history，历史快照只读，但允许播放与试动；不得只保存初始建议而丢失最新人工调整。
