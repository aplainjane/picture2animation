# 阶段06：Idle、Run 与动作过渡

输入：阶段05有效人工确认 `skeleton-animation-rig`。输出：idle、run、idle_to_run、run_to_idle 四段动作，动作检查网页、含素材的动作JSON、独立离线网页及最终动作确认。

需要参考现成动作时，读取[大肥鱼动作示例](../references/dafeiyu-motion-example.md)。其离线网页保留第70版已确认的素材、层序和动作；轻量动作JSON可用于分析节奏、交叉摆臂与小幅收步。移植前先核对目标角色，不复制示例的图片、节点坐标或确认状态。

## 网页使用与交接卡

路径中的 `P` 为当前角色项目绝对路径；见[统一目录与调用](../references/project-artifacts.md)。

- **调用工具**：`scripts/build_motion_review.py` 复用 `assets/motion-review.html`，并内嵌motion-runtime、motion-eyes和motion-material-editor，建议输出 `P/stage06-review.html`。
- **AI准备／提交**：有效的05确认，以及适配角色的idle、run、起跑／收步轨道和实时过渡。默认脚本提供Witch人形预设，需要先核对语义ID与体型；已有06项目从最新draft修订，不重新初始化。
- **用户怎么用**：播放四段动作、实时起跑／停下、慢放和拖时间轴，查看骨骼与面部；调层序，点选／双击部件手修，选两块进入双色像素转移。查看预览不提交数据。
- **保存与整阶段提交**：层序和反馈自动保存；画笔、橡皮及两层转移先点“保存素材”才提交，保存前的预览笔迹仍在本地。确认当前动作时点“确认最终动作”；导出当前交付不要求已有最终确认，但必须标记真实状态。
- **产出在哪里**：网页在 `P/stage06-review.html`；动作与人工覆盖在 `P/stage06-review.workflow/draft.json` 的 `production`，有效最终确认在同目录 `confirmed.json`。`layer_order/material_overrides/face_underlay` 均须保留。运行交付导出后得到 `P/delivery/animation-<run前8位>-r<revision>-<数据摘要前10位>-<页面摘要前8位>/`，内含 `character-idle-run.html`、`character-idle-run.json`、`release.json`。
- **交付／返修拿什么**：交付包包含已保存的素材覆盖、动作与过渡，可离线播放。以后局部修改继续使用该角色最新workflow；返回上游修订前先保存交付与历史，按稳定ID迁移人工成果，不把旧版最终确认套给新版。

## 读取确认与选定动作

运行 `scripts/review_checkpoint.py check --project <阶段05目录>`，只读取返回的 confirmed.json。原样沿用图像、PNG、节点、基础层序、绑定、人工六点与闭眼贴图；`rig` 整体在此阶段锁定。最终页局部修改与层序覆盖保存在 `production`，不回写已确认输入。动作写入独立的 `production`，不改阶段05的确认。现有阶段06应恢复其workflow，不能重新生成覆盖人工反馈。修改绑定或素材时返回对应阶段，经确认后再更新依赖。

按用户指定动作制作。当前采用用户指定的旧witch编排：4秒idle、0.5秒run循环、0.55秒起跑、0.85秒收步。参数可按角色修订。实际读原画判断视角，不把正面切片当作可直接大幅转身的侧面角色；沿用当前视角时明确交付原地跑步。

```bash
python scripts/build_motion_review.py --upstream rig.workflow --out stage06-review.html
python scripts/review_checkpoint.py serve --project stage06-review.workflow
python scripts/export_review_history.py --project-root <角色项目目录>
```

生成新阶段后启动服务，在应用浏览器打开URL。先看实际运行结果，再交付。原姿势必须逐像素复现确认素材；不能以默认动作某一帧代替原姿势检查。

## 动作设计

idle以温和呼吸、胸头小幅运动及延迟的发束／挂饰摆动为主；下肢配合呼吸做轻微屈伸，避免整个人僵直平移。表情继承已确认眼部渲染，自动眨眼独立于步频，不每一步眨眼。完全闭合使用对应闭眼贴图。

run使用相反的左右腿相位，并明确以左腿配右臂、右腿配左臂。不能只让两边肩角加相反符号：源上臂方向和肘弯也会改变视觉相位。当前 `witch_motion.py` 沿用旧witch的交替迈腿、屈膝、躯干前倾和双倍步频起伏，将旧版手臂方向映射到当前肩肘腕的原始方向，保留确认的手臂PNG。长靴继承小腿变换，避免在靴内踝节点折断靴筒。头发和裙摆采用顶部固定的条带位移，先在原像素离屏画布合成，再整体变换，避免条带经过旋转／缩放后产生横向裂缝。骨骼命名不匹配时先显式映射。

沿用旧witch的分段衔接：起跑前35%下蹲蓄力，后65%用easeOutBack蹬地进入跑步；收步前14%后仰急刹，至55%保持滑步，之后回弹到待机。过渡结束姿势应匹配目标循环实际推进的相位，不能无条件重置第0帧。循环首尾姿势相等，插值切线在循环接点一致。头发、裙摆、躯干轻微挤压与闭眼的效果轨道随动作保存。

移植参考动作时先核对左右命名：旧witch的手臂L/R指画面左右，当前人体骨骼l/r指角色自身左右。收步手势应双手向外抬起，必须用变换后的肩、肘、腕位置核对实际方向，不能只按同名后缀复制或只比较旋转角正负。单段手势映射修正不能全局交换已经通过检查的跑步摆臂相位；同时更新独立收步片段和实时过渡的skid姿势，并检查回到idle的端点。


网页同时提供四段独立检查和实际状态切换。播放中随时起跑／停下，从当前可见姿势快照过渡到正在推进的目标相位；中途反向切换或从单段／原姿势切换，也要先保留当前姿势。这里保证位置衔接；不应声称已有物理动力学、精确地面运动或速度连续的惯性混合。独立过渡片段保存从源动作第0相位起始的参考关键帧，实时切换另用快照混合。

## 网页、数据与检查

支持播放／暂停、四段选择、时间轴逐帧检查、慢放、连续演示、骨骼叠加、原姿势和面部放大。播放、速度、缩放、拖动与切换只改变预览，不保存草稿。检查状态与备注保存到 `production`；标记“需要修订”禁止确认。

动作轨道以秒、角度、原图像素表示，每节点一条轨道，关键帧 `[time, rotation_degrees, dx, dy]`。根到子的世界矩阵沿用父子层级：`parent × T(dx,dy) × T(支点) × R × S × T(-支点)`，躯干轻微挤压的S由效果轨道提供，其他节点默认单位缩放。JSON包含确认素材、绑定、眼部资产、动作轨道、过渡定义和上游版本，是本流程的原生格式，不能称作Spine工程。独立HTML内嵌脚本与素材，断网可用，不能提交确认。

至少检查：原姿势合成一致；idle/run接点；起跑和收步端点匹配目标相位；任意相位切换及中途打断无位置跳变；脚步不过度滑动或陷地；膝部、裙下、袖口、长靴连接无明显新露缝；原五官随头部同步；自动眨眼使用闭眼贴图；暂停、慢放、离线导出、历史及窄屏可用。出现素材缺口时记录部件／时间，不悄悄改已确认素材。

## 最终页图层与素材微调

用户可直接在最终动作页修小问题，边看动画边调整，无需为局部修补重复整条流程。图层列表顶部在前，提供上移、下移、置顶、置底、撤销和恢复基础层序；修改自动保存至 `production.layer_order`，必须是全部part_id的无重复排列。渲染、JSON与离线网页使用该顺序，基础 `order` 保留。

动画页默认支持按实际渲染alpha点选部件，包含骨骼变换、发丝条带位移与当前眼部贴图；透明背景不命中。单击选中并暂停，双击打开大窗口手修，拖动仍平移；Alt或中键直接平移，Ctrl/Command点击可切到同位置的下层，也可从重叠图层下拉框选择。Shift点选第二块，或点“点选两块”后依次点A、B，再点“编辑这两层”。点选与窗口操作不提交草稿。正在编辑未保存像素时，阻止切换选中部件，保留人工笔迹。

双层窗口按原图坐标一起显示两块，以青色A、橙色B标记，颜色仅用于识别，不写入素材。支持隐藏其他层、关闭双色标记、放大缩小与画笔光圈；旁边独立实时渲染动画，默认放大选中区域，可切回全身预览、播放或暂停。可切换编辑A或B；“扩大当前层”从另一层取像素，“划给另一层”将当前像素交给对方。两层沿用原图坐标，不能直接把动画变换后的屏幕位置当作像素坐标。

也可在图层列表选中后点击“手修选中素材”，提供取色、画笔、橡皮、平移、颜色、直径、局部原位编辑画布及其他部件淡显。主动画持续播放并实时使用编辑结果。取色选当前层／原图／原位合成；不是动画变换后的屏幕坐标。向透明处补画限原图范围，修改后收紧裁切、同步偏移。眼片保留原画布以保持六点与闭眼纹理对齐，这里修改睁眼贴图；需要改变眼部笼子或闭眼资产时回05处理。

“像素转移”选择对方图层和方向，将当前层像素划给对方或反向取回，只处理指定两层，透明背景不产生新像素。普通层不覆盖对方已有alpha，保持两层alpha总和；表情只与空面部交换。表情退回面部时RGBA覆盖贴回，表情清空；面部扩入表情时不覆盖已有表情及其他五官，面部恢复保存的干净底色，底色备份透明处保留当前面部。`production.face_underlay` 保存首次该版本面部交换前的底片，用于后续取回。两层一起实时更新、保存、撤销和取消，不能保存空部件。

修改先留在本地，点“保存素材”才把各层 `{x,y,w,h,src}` 同一请求写入 `production.material_overrides`，保存后的动画、动作JSON和独立HTML立即使用这些像素与坐标。保留part_id、绑定、节点、六点和动作；“恢复原素材”撤掉当前层覆盖。未保存时禁止确认、导出、切换编辑层和层序修改；离线交付与历史页保留已保存效果但不提交编辑。保存素材后动作回到待检查，不伪造人工确认。最终页普通草稿接口明确允许这些生产覆盖字段，源素材与完整rig仍锁定。

## 交付后返修与上游更新

交付是一个可用版本，之后仍可按用户指出的阶段、部件继续修改。小白缝、局部颜色或归属问题优先在最终页修补／转移；只调遮挡时直接调最终页层序。结构变化、需要AI大范围重绘等再返回相应阶段：轮廓归属02、补全计划03和素材04、节点01、绑定及闭眼05、动作06。渲染裂纹先修渲染器。

返修前保存当前交付HTML、JSON及各阶段历史。读取最新草稿和最终页的 `material_overrides/layer_order/face_underlay`，把人工修改当作当前成果，不从早期素材覆盖回来。按稳定part_id/node_id迁移绑定、六点、闭眼贴图、动作和人工像素修改；节点或画布变化须显式映射。最终页覆盖与上游同时改同一部件时做三方比较，保留不冲突的修改，冲突单独展示，不静默覆盖。

受影响下游应重新内嵌最新素材和坐标，更新依赖版本，先做静态合成与原动作回归，再交付更新后的动作页。可直接交付供预览的修订版，标明待检查，不要求用户重做未受影响的阶段；但不能沿用旧confirmed.json冒充新版本确认。需要正式放行时只核对变更影响与相应依赖；已有人工参数和旧交付均保留。不能仅替换磁盘PNG而让HTML仍播放旧素材。
