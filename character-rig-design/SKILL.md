# 角色动画设计主流程

本文件负责选择阶段、加载子流程和衔接阶段结果。每个阶段的详细执行说明独立放在 `stages/`，按需读取。

## 网页模板与复用入口

六阶段前端及其运行脚本已保存在本 skill 的 `assets/` 与 `scripts/`。执行时复用对应模板，由生成脚本注入当前角色数据；不为新角色重新编写前端，也不把角色图片、坐标或人工修改写进模板。第一次在新项目使用，或需要迁移／恢复已有项目时，读取[模板对应关系与复用规则](references/template-reuse.md)。角色分析、拆分边界、隐藏素材补全及动作适配仍按阶段制作，不能将模板复用描述成任意原图一键自动完成。

每个阶段开头的“网页使用与交接卡”规定输入、用户操作、保存／提交、产物位置与下游读取方式。执行前读取[项目产物与交接约定](references/project-artifacts.md)，确定角色项目绝对路径；阶段交付时告知实际网页URL、workflow目录、当前修订／确认状态和下一步所读文件，不能只说“已生成”。

阶段06附带[大肥鱼动作示例](references/dafeiyu-motion-example.md)，包含已确认的idle、run、起跑与收步，可离线播放。需要参考本次动作时按该说明读取；示例素材和坐标不作为新角色的默认输入。

## 共同约定

- 采用设计者已确定的部件、骨骼节点、命名和连接关系，区分设计决定、AI 建议及尚未确定的内容。
- 新的完整人形方案先采用阶段 01 的人体基础骨架，再追加附件控制；设计者可调整位置、命名、细分或明确采用简化方案。
- 保持原图、坐标系、部件 ID 和节点 ID 在阶段间可追溯；变更时同步受影响的结果。
- 不将旧角色案例的部件、坐标或动作直接当作新角色的设计。

## 选择并启动阶段

1. 根据用户当前要求和已有成果选择阶段。用户明确指定阶段时优先使用该阶段；只有原画、希望开始角色分析时进入阶段 01。
2. 读取下表所链接的阶段文件，并按其输入、流程和输出执行。加载子文档即在当前任务中开展对应子流程，无需用户再次调用子 skill。
3. 输入不足时先完成可独立进行的工作，再索取缺少的信息；涉及图片定位时必须实际读取图片。
4. 交付当前阶段成果，标明已确定设计、建议和待定项。按用户要求继续修订或转入下一阶段。

## Checkpoint：人工确认后再进入下一阶段

每个阶段生成网页时同时建立独立检查点项目；启动本地审阅服务并在应用浏览器打开服务返回的 URL，不能只交付文件链接。按照当前阶段子文档中的 checkpoint 流程等待人工操作。

- 网页的整阶段确认按钮是明确放行操作，服务写出包含设计快照的 `confirmed.json`；普通导出、保存、单项确认和打开网页都不放行。
- 每次进入依赖本阶段的后续流程前，运行检查脚本。只认本次 `run_id`、图片和最新草稿均匹配的有效确认，不以文件存在、节点显示绿色或聊天中的含糊表述代替检查。
- 人工继续修改时检查点回到等待确认；重新生成网页会创建新任务，旧确认无效。恢复任务应读取已有项目并启动审阅服务，不重新生成并覆盖人工成果。
- AI 不自行写入确认标识或调用确认接口来替代人工点击。用户尚未完成确认时停在检查点；这里的等待是用户明确要求的流程设计。
- 正在执行的 skill 可用有界等待检查文件后继续；确认文件本身不会唤醒已经结束的 AI 会话。会话恢复后先检查已有 checkpoint，再从对应阶段继续。

当前实现阶段 01–06。阶段 03 确认处理计划；阶段 04 按计划修复素材并单独确认结果；阶段 05 检查骨骼绑定；阶段 06 制作具体动作及过渡。隐藏区域的推测补全需要检查，不能把静态审阅当作动画验证。

| 阶段 | 何时启动 | 子流程文件 | 交付内容 |
| --- | --- | --- | --- |
| 01：角色结构设计 | 识别部件、讨论拆分、规划骨骼或判断局部重绘区域 | [角色结构设计](stages/01-character-structure.md) | 部件方案、可调整骨骼的原图网页、结构 JSON、素材处理建议 |
| 02：角色拆图与表情分离 | 骨骼设计已确认，需切出角色部件并检查轮廓、顺序和面部 | [角色拆图与表情分离](stages/02-part-separation.md) | 透明 PNG、彩色外形与图层编号网页、空面部及独立表情、本阶段确认 |
| 03：补全与局部 SVG 重绘计划 | 切片已确认，需逐块查看完整性、散点和重绘必要性 | [补全与重绘计划](stages/03-material-completion.md) | 全部独立切片网页、AI处理建议与范围、可勾选的补全/SVG/清理清单、计划确认 |
| 04：素材修复与结果检查 | 处理计划已确认，执行补全／局部SVG并检查结果 | [素材修复与结果检查](stages/04-material-result.md) | 前后对照网页、原位合成、透明PNG、真实SVG、坐标与素材包、独立结果确认 |
| 05：骨骼绑定与动作检查 | 素材结果已确认，准备骨骼动画 | [骨骼绑定与动作检查](stages/05-skeleton-animation.md) | 可调整绑定与摆幅的网页、关节试动、轻量待机、绑定JSON、独立预览、检查确认 |
| 06：动作制作与过渡 | 绑定已确认，制作idle/run与起停动作 | [动作制作](stages/06-motion-production.md) | 四段动作与交互切换、时间轴、动画点选、双层双色边界编辑、动作JSON、离线网页、最终动作确认 |

阶段 02 依赖阶段 01 的有效确认，并持续绑定该骨骼版本；上游修改后需要核对并重新生成。空面部与表情分离是第二阶段必需交付，不能沿用带原五官的脸再叠第二套表情。

阶段 03 读取阶段 02 的有效确认快照，连带绑定阶段 01。只修改处理计划，不能回写已确认切片；用户可取消全部建议，也可为原本建议保留的部件追加处理。

阶段 04 读取阶段 03 的有效确认快照，只执行已勾选动作。未选部件保持逐像素一致，结果确认前不能进入动画流程。

阶段 05 读取阶段 04 的有效确认快照，包括人工画笔与橡皮后的最新素材。沿用节点与层序，仅编辑绑定和动作参数；发现露缝则记录问题并返回相应设计阶段修订。阶段 06 读取阶段 05 确认快照，锁定绑定与表情资产，制作用户要求的具体动作和过渡。当前素材采用刚性切片；跑步采用用户指定的witch动作编排与分段起停过渡，未实现网格蒙皮或Spine工程导出。

涉及自然眨眼时，阶段02、03、05共用[眼部拆分与眨眼设计](references/eye-blink-design.md)：分开眼球内容与眼睑遮罩，保留原眼线纹理，设计连续开合形状与时序。已确认的合并眼片只能做标明局限的派生预览，不能通过整眼压缩冒充完成的表情资产。

## 流程回看

生成当前阶段和每次阶段交接时，运行 `python scripts/export_review_history.py --project-root <角色项目目录>`，把最新草稿或确认快照导出到项目的 `history/`，更新 `review-history.html`。服务端整阶段确认也会追加只读快照。历史页保存真实编辑后的数据，不能只链接最初生成、可能已过时的网页。快照可离线浏览和缩放；继续编辑须恢复已有 workflow 的本地服务，不重新生成覆盖人工成果。保存的是阶段快照，不是每次鼠标操作的录像。

## 阶段衔接

- 遵循用户逐步推进的节奏；设计者在网页点击阶段确认后，主流程可进入已实现且在用户任务范围内的下一阶段，仍须通过 checkpoint 检查。仅调整或导出草稿不算确认。
- 进入后续阶段时使用已有成果；只有缺失或发生相关设计变更时才回到前置阶段补充。
- 每次交接说明使用的原图与坐标系、沿用的部件和节点、设计者已作的决定，以及会影响下一步的待定项。

## 扩展阶段

每建立一个阶段，在 `stages/` 增加一个 `NN-stage-name.md` 文件，写明输入、执行流程、输出及完成条件，并更新主文件的阶段表与依赖说明。共用约定留在主文件，详细规则写进对应子文档；执行任务时仅加载当前所需阶段。

交付后仍可局部返修。小白缝、改色、像素归属或遮挡调整，优先用[最终页图层与素材微调](stages/06-motion-production.md#最终页图层与素材微调)实时修改；结构或大幅素材变更按[交付后返修与上游更新](stages/06-motion-production.md#交付后返修与上游更新)返回对应阶段，保留人工成果并更新后续网页内嵌素材。交付不以最终确认作为阻塞，确认状态须如实标明。
