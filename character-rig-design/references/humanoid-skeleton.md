# 人形基础骨架与 Spine 参考

在阶段 01 为完整人形角色设计节点时读取。本文规定本 skill 的基础人体结构，参考 Spine 的层级与官方案例；不是 Spine 官方强制标准，也不是可直接导入 Spine 的骨架文件。

## 官方参考与适用范围

核对日期：2026-10-16。示例 JSON 使用官方 spine-runtimes 的 `4.2` 分支，文件中的导出版本为 `4.2.22`；官网文档可能展示其他版本。

- [Spine Bones](https://esotericsoftware.com/spine-bones)：骨骼是变换层级，单个 skeleton 有一个 root；父骨骼变换影响子骨骼。不要求固定的人体名称或关节数。图片通过 slot/attachment 关联，骨骼数量与图片数量不必一致。
- [Spineboy](https://esotericsoftware.com/spine-examples-spineboy)：`hip` 与全局 `root` 分离，脚部 IK 目标与 `hip` 位于同一级，便于身体移动时脚保持在原位；大腿、小腿、脚分别控制。
- [Spineboy 官方骨架数据](https://github.com/EsotericSoftware/spine-runtimes/blob/4.2/examples/spineboy/export/spineboy-pro.json)：可核对 `root → hip → torso → torso2 → torso3 → neck → head` 和腿部链。该文件共 67 根骨骼，包含道具、约束辅助等，不能把总数当成人体标准。
- [Stretchyman](https://esotericsoftware.com/spine-examples-stretchyman)：控制四肢的两骨骼 IK，与沿路径分布、负责网格变形的多段骨骼分开。说明简单控制层与更细的变形层可以共存。
- [IK constraints](https://esotericsoftware.com/spine-ik-constraints)：两骨骼 IK 常用于上臂/前臂、大腿/小腿；目标不能是受约束骨骼的后代。IK 属于后续绑定与动画设计，本阶段先保留结构基础，不把标注点等同于已实现的 IK。

## 本 skill 的默认：18 个基础节点

完整人形角色必须先规划下列基础节点，再追加头发、衣服、饰品等控制点。不能因为衣服或长发遮住肩、肘、髋、膝，就省略对应身体节点。被遮住的位置标为 `placement: inferred`，让设计者在原图网页调整。

| 分组 | 建议 ID | 数量 | 定位含义 |
| --- | --- | --- | --- |
| 总根 | `root` | 1 | 全角色移动控制；可放地面中心，具体由设计者确定 |
| 骨盆中心 | `pelvis` | 1 | 骨盆整体控制，区别于左右髋关节与总根 |
| 腰部 | `spine` | 1 | 腰腹弯曲与上下身连接，不沿裙摆边缘定位 |
| 胸部 | `chest` | 1 | 胸廓控制，作为颈部及双臂链的上游 |
| 颈部 | `neck` | 1 | 颈根、连接胸廓与头部 |
| 头部 | `head` | 1 | 头颅转动支点，通常位于上颈与头颅连接处；不是头顶装饰的挂点 |
| 左右肩 | `shoulder_l / shoulder_r` | 2 | 肩关节、上臂运动起点 |
| 左右肘 | `elbow_l / elbow_r` | 2 | 上臂与前臂连接 |
| 左右腕 | `wrist_l / wrist_r` | 2 | 前臂与手连接 |
| 左右髋 | `hip_l / hip_r` | 2 | 左右大腿起点，不用一个骨盆点代替两侧髋 |
| 左右膝 | `knee_l / knee_r` | 2 | 大腿与小腿连接 |
| 左右踝 | `ankle_l / ankle_r` | 2 | 小腿与脚连接，不能用靴底或脚尖代替 |

共 18 个：身体中轴 6 个，加双臂 6 个、双腿 6 个。`root` 是全局控制点，其余是人体支点或区域控制，并非全部都是解剖学关节。这里是适合编辑网页的节点约定；导出为真正的 Spine 骨骼时，还需要处理骨骼原点、朝向、长度和父空间坐标。

默认左右指角色自身的左/右，不随截图镜像或绘制先后改变。已经采用画面左右、近侧/远侧 ID 的项目保留原 ID，说明语义对应，不擅自重命名。

## 默认层级

```text
root
└─ pelvis
   ├─ spine
   │  └─ chest
   │     ├─ neck
   │     │  └─ head
   │     ├─ shoulder_l → elbow_l → wrist_l
   │     └─ shoulder_r → elbow_r → wrist_r
   ├─ hip_l → knee_l → ankle_l
   └─ hip_r → knee_r → ankle_r
```

胸部带动颈、头和双臂，骨盆带动双腿。脚踝不要挂到裙摆，手腕不要挂到袖口，头部不要挂到帽子。服装与附件节点在身体骨架上追加：帽子跟随头、裙子跟随骨盆或腰部，再按动作设计分支。

设计者可以在链上增加锁骨、多段脊柱、头部控制、手掌、脚跟/脚尖等节点，不要求基础节点必须直接相邻。改用约束或特殊层级时记录控制关系及原因，不能只看到节点名字齐全就认为结构正确。

## 可选层与素材拆分

- 足尖/足跟：需要脚掌滚动、踮脚或走跑时追加。
- 掌心、手指：需要手势时追加；腕点不能表达全部手部运动。
- 锁骨、肩胛、多段脊柱、柔性肢段：需要更细的变形时追加。
- 手脚 IK 目标和其他控制器：独立于身体链规划，目标不要成为受约束肢段的后代。
- 眼睛、眉毛、嘴、头发、裙摆、帽尖及挂饰：独立的表情或附件控制，不占基础人体节点名额。

身体节点齐全不意味着强制切成 18 张图片。肘节点可以先存在于一张完整手臂素材中，后续选择切片或网格绑定；没有肘节点则难以表达前臂相对上臂弯曲。拆图仍按动作、遮挡与素材条件确定。

## 第一阶段检查与已有项目

对完整人形交付前逐项核对：18 个语义位置齐全；左右侧明确；中轴、双臂、双腿链正确；遮挡节点注明推测；附件没有替代人体节点；原图坐标与关节位置由设计者检查。

仅头像、半身裁剪、缺肢设计或非人形不强塞全身模板；明确记录适用范围及不适用节点。无法在当前图片范围定位的部分不编造坐标或塞到图边缘。设计者明确选择简化方案时记录其决定，不能默默遗漏节点。

本规范不追溯重写已经确认的项目。需要升级旧骨架时，先保留当前草稿和后续人工成果，再从实际图片补节点、重新审阅；骨骼改变会使依赖它的后续确认失效，不能沿用旧确认来声称新骨架已获批准。

当前网页支持添加、连接和拖动任意节点，但还没有自动补齐这 18 个节点或按人体语义检查缺项的功能。此版本由执行阶段 01 的 AI 按本清单检查，网页整阶段确认仍由设计者完成；不要宣称程序已强制校验节点完整性。
